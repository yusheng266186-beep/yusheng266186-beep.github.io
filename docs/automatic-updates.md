# 自动采集与发布

网站由 GitHub Actions 更新，不依赖某台电脑、本地预览进程或访客打开页面。

`Refresh Research Pipeline` 在一个有限窗口内最多运行 8 轮，正常每 5 分钟开始一轮，结束后用仓库自带的 `GITHUB_TOKEN` 请求下一窗口。全仓共用一个采集并发锁；定时备用启动和接续请求只能排队，不会同时写数据。窗口最长 55 分钟，单轮采集进程最多 6 分钟；连续两轮发生关键失败就重启窗口。无需新增个人访问令牌。

每轮并行检查国内行情、资讯、市场因子及到期的历史数据，再更新首次见到的输入存档、预测发布、到期账本和证据研究台。日级国际金价/汇率组件每 6 小时核对，已完成日线按需补抓；不会把日级资料伪装成逐笔实时数据。AI 解读沿用“材料变化、至少间隔 60 分钟、每日最多 12 次”的既有上限；定时采集不会重跑封存模型实验。

每轮仅提交 `data/*.json` 与 `data/embedded-data.js`。并发代码提交会通过普通 rebase 保留；遇到数据冲突不强推，保留远端数据并重新从 main 启动。每轮提交后明确请求 Pages 发布，避免 `GITHUB_TOKEN` 提交不会自动触发 push 工作流的问题。前台每分钟核对带分钟版本的同源公开快照，重新联网或返回标签页时也会检查，最新行情随研究包一起到达；手动校准价格不被自动覆盖。

`Research Recovery Watchdog` 目标每 10 分钟检查，并在采集工作流结束时检查。没有活动窗口且回执超过 12 分钟、关键失败或交接失败时会补启动；同一窗口超过 20 分钟且采集回执超过 15 分钟未变，会取消卡住的窗口并重新排队。巡检只操作本站采集工作流。旧的三个手动更新入口也调用同一完整流程，避免各自发布半套资料。

## 时间的含义

- 行情报价时点：来源最后一笔真实报价，休市或无新成交时保持原值。
- 行情来源核对：最近请求行情源的时间，即使没新价格也可前进；失败不改报价时点。
- 资讯最近核对：最近采集资讯源的时间。没新文章不等于没采集。
- 原文最新发布：发布者给出的文章时间，与抓取时间分开。
- 后台采集完成：本轮处理与公开快照装配的时间。`pipeline-health.json` 同时记录各阶段、各渠道、失败连续次数和任务链接；来源失败不能被成功的脚本退出码掩盖。

## 操作与边界

正常使用不需要人工点刷新。可在 Actions 手动运行主流程；`rounds=1`、`continue_service=false` 为一次性修复，`rounds=2` 可检查相隔五分钟的两轮及自动交接。正常服务使用默认 8 轮和自动接续。

暂停时将仓库 Actions 变量 `AURUM_UPDATES_PAUSED` 设为 `true`，并取消当前采集任务；恢复时删掉或设为 `false`，手动启动一次主流程即可。禁用主工作流也会阻止接续，但应同时暂停巡检。没有在网页内暴露 Actions 凭据或可触发付费 AI 的接口。

GitHub Actions 调度、运行器、Pages 发布和公开来源均可能延迟或中断，因此 5 分钟是正常运行目标，不是实时服务承诺。来源拒绝访问、休市、平台故障或额度限制时保留最后有效数据及原时间，显示实际失败；不把当前时钟写成新报价。停用仓库、移除密钥或上游接口永久变更仍需要维护。
